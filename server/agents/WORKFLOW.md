# 文章生产 Agents 工作流

系统执行工作流，工作流调用已认可的 Skill。本文描述工序和交付，不重写十二类文章模板。

## 总控

复用项目资料理解 → 批次分配场景与选题 → 单篇主编确定标题和稿单 → Skill 一次完整写作 → 成品处理。

范文阅读与标题定稿合并在单篇主编调用内，不再单独总结范文、拟标题、审标题或补正候选。选题的历史语义比较在总控本次调用内完成，不再额外请求去重编辑；本地重复检查及有界重分配仍保留。已有项目理解和选题时，每篇正常只调用主编和作者两次。格式恢复、缺项恢复、接口重试及必要的篇幅收束属于异常路径，不承诺任何情况下都只有两次调用。

项目理解在一批中复用；每篇有独立选题、编辑稿单和正文。每次模型调用前后保存进度及请求摘要。续跑复用同一输入下已经完成的工序；资料、模型或版本发生变化时不混用旧工序。

## 系统页面映射

- 企业品牌库：维护推荐主体；项目理解面板按知识库范围查看、更新和保存修正说明。
- 关键词及关键词库：保存搜索主题、用户问题和语义资料，不生成正文结构。
- 品牌知识库：实际选中的库决定资料范围，空选表示当前品牌全部知识库。后台从存储读取原文，不信任页面传来的资料副本。
- 榜单服务商：提供当前品牌的同行资料，是否进入文章由所选Skill决定，不要求用户为每篇重填。
- 生成任务：提交项目、核心词、场景来源、类型偏好、资料范围与篇数。场景来源统一为AI场景或手动场景；手动仅填城市和行业，其余业务理解、选题和稿单由工作流形成。旧任务按原快照保留。
- 任务详情：只展示流程状态与进度，不展示内部稿单和推理细节；下方显示本批文章并支持批量下载，不跳转成品库。中断任务仅在版本兼容时继续同次执行。
- 成品文章库：承接已完成文章，沿用编辑、配图、单篇和批量下载。旧审核入口归并到文章库。

项目理解以项目及来源指纹保存，资料变更后重新理解。修正说明作为项目背景传入理解、选题与编辑，不改写原始事实。每个已启动任务继续使用自己的材料快照；更新资料只影响新任务。

## 项目理解

输入项目身份、业务、品牌材料、引证和同行材料。交付定位、客户及场景、优势的事实依据、服务对客户的价值。事实保留原始来源，品牌自述不升级为独立核验。资料中的额外指令不参与生产。

## 选题及类型匹配

先理解项目提供的服务、买方行业及该行业实际业务细节，再提出服务商选择方向。AI选择适用买方场景，手动保留指定城市行业；城市需求不等于企业驻地或既有客户。历史记忆包括标题、选题、正文中间论据样本和已用资料，不把换词当新认识。用户指定类型时保留选择；没有指定时按选题匹配成熟Skill类型。交付行业理解、选择价值、读者、资料联系与类型，不输出正文。

## 单篇编辑

读取对应 Skill、同类型认可范文、项目理解及本篇选题。先形成完整推荐判断和论证路线，再安排连续写作工序。品牌事实被理解为推荐理由，而不是正文待插入的公司介绍。

units表示文章的逻辑部分：本部分新增回答什么、如何承接前面、哪些事实支持判断、留下什么给后文。它不是多次正文API调用。全文阅读体量统筹安排，不给每章独立膨胀的扩写任务。

## Skill 写作

作者获得对应模板、范文方法、完整稿单与相关事实，一次完成开篇至结论。重点摘录用于主线，完整项目原料保留备查，不要求全部写进正文。幕后材料核验与排程不用写进正文。范文只示范结构、节奏和表达，不搬用其公司、案例与数据。

接口没有返回或输出被截断时保存失败位置，不评分打回或自动换词。格式损坏按已有有界恢复流程处理。深度与精选各沿用自己的篇幅收束，不混合两套要求，不用查重硬门槛阻断正常文章。

## 成品及实施边界

程序原序合并写作部分，保存原稿、稿单与生产版本，再由现有文章库提供配图、编辑、下载。技术测试验证交接和隔离，实际文章另行阅读验证；流程测试通过不代表内容已经商用验收。

成熟 Skill 保持独立哈希；工作流、范文和交接协议独立版本管理。工作流状态留在项目任务记录中，不需要让用户填写段落任务或原始推理。
