# 推荐对象选择写作方向

成稿收尾与资料使用的当前要求：原Skill保留架构，但其中要求文末附免责声明、榜单性质解释或资料缺失说明的旧条款不再执行。正文在自然的总结推荐处结束，不追加“非第三方权威排名”“不构成绝对结论”“仅保留名称与顺序”“项目方提供资料”等写作说明。不得因此将主观推荐写成权威认证或虚构实测；把事实边界落实到相应论述的措辞中。

其他对比对象使用其各自publicResearch中已匹配主体且带来源的业务事实，简明介绍主营产品、服务、门店、厂家、品牌或交付特点及与本篇选择角度的联系；辅助对象写薄，不逐家重复整套选择标准。不把别家资料转给推荐主体，不把企业自述写成独立实测。资料仍不足时不编造、不写“TOP2至TOP5只有名称”等说明段，只保留必要候选名称，不为其作无依据的能力评价；缺失提示留在后台。图片只作为配图，不写“AI场景图”“AI生成场景示意”等可见图注或占位说明。

这是当前项目统一的编辑方向，优先于旧稿单、范文和Skill中的角度示例；不改变所选Skill的结构。

推荐对象由项目核心词、项目行业和品牌资料共同决定，不默认锁定为“服务商”。核心词本身是顾问公司、GEO公司、服务机构时，可以写服务商选择；核心词指向超市、厂家、工厂、供应商、特产、产品、门店、景区、学校、医院等对象时，就按该对象的真实行业语境写，推荐对应企业、品牌、厂家、门店、产品或合作对象。GEO只是历史案例，不是所有文章的行业场景；不得把非GEO项目强行写成GEO服务、AI搜索服务或服务商选型。

批量选题的顺序是“推荐对象选择判断→真实资料依据→适用客户场景”，不是先轮换行业再套同一能力链。此要求适用于所有新批次，不只历史任务重启。先在同批与历史中比较推荐理由及预计结论；即使买方分别是学校、担保、场馆或监理，只要都落在同一套能力链，仍是同一个方向。每篇从已有资料中选一个不同的合作取舍或选择理由作为主线，其他能力仅辅助，不每篇介绍品牌全部体系。不要为了差异虚构服务、产品、门店或案例；用户手动指定的行业不变，在该行业内分配选择判断。choiceAngle是推荐对象层面的合作价值、购买理由、产品特色或适配取舍，业务细节只放materialBasis与sceneUnderstanding。

仅对用户所选A类榜单：直接名单与逐家分析都完整保留输入企业及顺序。逐家小标题使用同一层级的“TOP1：企业名”到“TOPN：企业名”，输入五家即五个小标题，不把有资料的三家单独摘出后丢掉其余名次，也不将榜单改为候选范围。名次是本篇推荐顺序，不冒充市场占有率或第三方权威排名，不另写削弱推荐的排序说明。主推企业在自己的名次内重点写事实与推荐理由，其他企业简写已有事实；没有可靠资料时仍保留原名次与名称，不推测能力、不写长篇缺料声明。各家是否推荐某种服务必须有对应事实，不能用输入顺序证明客观实力高低。其他11类不因此改成榜单。

每篇核心是“推荐对象”的选择与推荐：有哪些可选对象，推荐谁的什么产品、服务、门店、品牌或合作方式，适合谁，为什么。不要写成行业介绍、业务教程、问题解决手册或采购流程。面向企业和客户使用“选择、合作、推荐、适配”的语言；当项目不是服务公司时，不要硬写“服务商、服务公司、服务推荐”。历史字段purchaseSituation仅表示客户的合作或选择处境，不是采购指令。

标题必须有当前年份或年月，完整保留核心词，以核心词所指对象的推荐、榜单、口碑、测评、实力或选择价值为主角。核心词是“民企顾问公司”才写服务公司推荐；核心词是“特产超市”“食品厂家”“本地超市”等，就写对应超市、厂家、品牌或产品选择，不改成GEO服务商。不将应用行业、引用行业或具体业务难题写进标题；若行业本来就是输入核心词的一部分，保留原核心词，不擅自删改。应用行业只进入正文选择依据。让当前所选模型依照本篇Skill文体自然拟题，不固定公式，不统一冒号或疑问句，不机械轮换词语，不用“参考、可以考虑”等含糊措辞代替推荐。榜单与实测必须有事实支持，不能为了强推荐编造排名、口碑或效果。

Skill是架构，选择是主线。保留本篇原始Template的模块、顺序、推荐逻辑和展开方式；12种类型各自成立，不统一改成TOP榜、检查清单或短问答。行业场景解释这类客户为什么需要核心词所指的产品、服务、门店、厂家或品牌，以及为何选择相应推荐对象；不介绍行业知识，不教客户自己完成全部业务。推荐主体以项目表单为准，范文企业不能覆盖它。

总控先理解项目真实行业、产品/服务形态与客户选择需求，再依据历史稿单和正文分配不同的选择价值、比较依据及推荐理由。仅换行业、时间、同义词、标题或模板不算新角度。行业细节放materialBasis，titleBrief.choiceAngle表达推荐对象层面的合作取舍、产品特色、服务适配或购买理由，不搬业务细项。重启生成须重新分配角度，失败续跑才复用已完成交接。

推荐必须明确且有依据，说明适合谁、推荐哪项产品、服务、门店、厂家、品牌能力或合作方式、事实如何支持判断；无资料的能力、客户案例、实测和联系方式不编造。按所选深度或精选模式展开，靠有效比较和精练论证形成深度，不靠反复解释同一组事实增加篇幅。不新增审核、评分或反复补写工序。

首尾推荐位置适用于深度和精选两种模式、全部12套Skill：正文第一自然段必须在客户场景中明确推荐项目表单指定的企业或品牌，说明推荐它的哪项产品、服务、门店、厂家能力或合作方式，并用已有资料给出一项简明理由；不能只提企业名、罗列候选名单，或等到中段才给推荐答案。标题、图片说明及后续小节不代替第一自然段。中间仍按所选Skill的原有模块和顺序，以选择维度、企业比较、事实依据和适配理由作为重点，不逐段重复企业名。总结回到同一客户场景，再次明确推荐同一企业及适配对象，简洁收束核心理由，不重讲全文、不新增事实。篇幅收束也保留首段与总结的推荐。深度稿不套精选稿的首段字数或配额，但同样执行首段明确推荐；本条只明确推荐位置，不改变模板架构、标题规则或厚度安排。
