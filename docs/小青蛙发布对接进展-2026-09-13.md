# 小青蛙发布对接进展

## 已实现

- 已验收管理、额度及恢复修复同步新站，部署前生成并校验一致性备份，不操作旧站。
- 新闻源与第三方自媒体分别调用 media 与 zi_media_api 接口。
- 统一媒体列表、投稿、订单查询客户端；真实列表读取已验证，投稿及订单查询使用隔离响应测试，未发送付费投稿。
- 报价采用整数分，拒绝无效价格；媒体案例仅允许 HTTP/HTTPS 链接。
- 投稿受理保存为 submitted 语义，不把取得订单号当作已发布。
- 投稿超时或响应异常标记结果不确定，不自动重试。
- 暂停旧的裸投稿入口，防止绕过客户额度和订单账本。连通性检测保留。
- 页面切换媒体渠道后忽略旧请求结果，避免新闻源与自媒体列表串页。
- `npm test` 75 项回归通过，`npm run test:media` 4 项通过。

## 下一段落地

1. 服务器根据所选文章与媒体生成报价快照，不能信任浏览器传入的价格。
2. 发布订单关联品牌项目、客户、代理、文章副本与媒体；锁定销售价格、成本、加价。
3. 客户确认后原子预占余额及发布额度，持久化单篇投稿编号，再调用平台。
4. 超时保留待核实，不退款后盲目重发；查询确认后再结算或退回。
5. 状态、链接、退稿原因回写发布记录，任务内显示已发布与未发布。

## 待核实的供应商约定

- 当前订单示例只展示 status=4 与 is_refund=1，不足以确定完整发布/退稿状态枚举及链接字段。
- 文档提供 third_id，但需核实重复编号是否幂等、能否用此编号查询超时订单。不能假定重复调用安全。
- 文档默认服务地址是 HTTP，正式收费开放前应向平台核实可用 HTTPS 入口。
- 正式付费提交、真实退款未验收，不标记整个发布系统已完成。
