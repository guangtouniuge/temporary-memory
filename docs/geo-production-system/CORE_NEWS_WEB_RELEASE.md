# 核心新闻源网页接入（2026-09-16）

用户要求在普通浏览器中的原系统直接操作，不使用另开的桌面工作台。本次网页方案替代桌面试用方案作为当前入口。

- 原路径：`/gongju/agents#/project/core-news`。
- `public/core-news-browser.js` 仅增强核心新闻源页面，其余路由不变。
- 独立服务 `server/core-news-browser.mjs`，监听回环地址8792；Nginx只新增`/api/core-news-browser/`代理。
- 每次操作由现有文章API校验登录和企业项目身份；浏览器会话按用户和项目隔离。项目品牌文章仍从原API只读获取。
- 服务浏览器打开HTTP新闻平台，通过原系统HTTPS页面显示画面、接收点击和文字输入；未忽略TLS证书错误。
- 专用低权限系统账号、Chromium沙箱、内存限制、最多2个会话、闲置10分钟释放进程；仅允许新闻站网络请求，不提供任意网址或代码执行接口。
- 标题正文填入前确认，不覆盖已有内容；不会自动选择媒体或提交付费订单。图片上传和审核状态自动关联尚未实现。
- 原系统主JS/CSS由当前线上版本原样复制，只在HTML额外挂载新闻组件。没有整体发布脏工作区，也不重启文章生成服务。

本地验证：完整原系统页面布局、读取文章与20条分页、按钮实际调用、点击及文字输入、服务身份边界、真实浏览器会话隔离；测试均使用临时目录及隔离本地数据。

线上只读验证：页面和组件可访问、无登录访问被拒绝、原系统主脚本哈希不变、原文章服务保持运行。真实账户登录后的发布编辑器仍需用户登录验证，不将本地模拟结果描述为真实订单已发布。

## 输入与批次修订

- 登录表单位置提供真实输入控件，支持输入、粘贴替换、中文输入和密码掩码，逐字段同步远端；密码值不在画面状态接口回传。旧版仅用隐藏输入区转发按键的体验不作为已验收登录能力。
- 文章按已有任务批次读取，展示计划、已生成与实际可用篇数。存在jobId时直接读取该任务结果，不混入其他批次或品牌文章。
- 可尝试从平台勾选表格读取媒体编号、分类和单价，并设置每个媒体的篇数；不识别的页面明确失败，不猜测编号或价格。
- 当前匹配仅为分类规则与顺序分配清单，校验总量、重复媒体、重复文章与费用。**尚非完整Agent发布器，没有开放自动提交订单**；真实平台媒体页面、价格复核、提交和订单回执还需要在用户登录后适配。
- 批次改为每页20条的复选表格，支持跨页多选、全选本页、清空选择，最多50批；合并读取实际完整文章并按ID去重，显示每批计数与合计。改变勾选会清空旧文章和媒体分配，避免使用过期选择。
- 发布工作台左侧多选文章批次、右侧分配平台媒体与篇数，可平均分配；顶部“新闻平台”标签与工作台分离，切换时保留选择。“平台登录”和“发稿列表”在当前受控会话打开固定路径。
- 客户端使用同一前端，通过限定IPC动作连接独立原生WebContentsView，真实输入而非截图。普通网页版仍使用远端受控画面。`desktop-news/start.ps1`启动本地更新后的客户端，未覆盖其他视频客户端。
- 当前没有订单历史同步，不将完整文章数标记成未发布数。真实平台的自动下单仍未开放。
- 新增完整页面到远端密码框的键盘输入及粘贴替换、多批次去重与跨页勾选测试；13项相关测试通过，均使用隔离本地数据。
