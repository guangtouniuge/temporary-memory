# 本批五篇文章与成熟样本对照

## 范围

读取当前本地platform项目文章库5篇正文、当前项目资料、对应任务的真实选题与单篇编辑交接，并通过浏览器检查第一篇全文显示。对照已保存的企来客样本21440654、21549415、21549439，以及冻结Skill配套的历史认可范文。未修改Skill、生产提示词或文章，也未新增模型调用。

企来客样本仅用来对照表达与组织，不代表其中统计、客户案例和算法说法已核实。当前5篇也不能代表全部12类已完成质量验收。

## 主要发现

1. 生产路线已经有效。五篇有各自的问题、段落结构和企业推荐，品牌事实进入理由，不再只是字段拼接。不能因此又替换原有Skill或重造生成器。
2. 选题仍过近。五份真实选题主要围绕如何判断靠谱、核验、稳定性与长期合作，差别更多在文体，而不是购买处境。五篇反复展开自研、本地、数据后台、合规。项目理解给出了完整优势清单，但单篇选题尚未充分取舍。
3. 稿单给出的推荐答案仍偏候选。榜单编辑稿单写“值得放进第一轮对比”；选型正文进一步写“注意，是重点对比，不是直接选”。不是后处理替换，而是编辑阶段已如此定调，作者又进一步放大。应在稿单中形成需求、适配品牌及最关键理由的明确答案，不靠禁用“参考”解决。
4. 结构齐全但信息重复。避坑稿先写技术、本地、后台等坑点，再写同样的标准，接着品牌逐条对应、签约问题和FAQ再次复述。榜单中7×12与48小时分别重复3次。成熟对照样本会以服务过程、需求分流、企业特点增加信息；不能只学习其模块数量。
5. 工序承接仍有编辑旁白。测评稿出现“五家拆完后，读者需要知道怎么把测评结论用到自己的选择中。接下来解释……”。这是后台任务说明进入正文，不是读者需要的论述。应该把下一工序要回答的问题写清，同时让作者用内容关系承接，而非讲述自己正在写作。
6. 同行特点没有稳定事实底座。当前同行库仅有四家公司名称，类型均为“对比公司”，其余事实栏为空。榜单稿把企来客写成官网承接优化，测评稿写成预算有限的基础曝光测试；欧博东方也发生定位漂移。当前材料无法支持这些判断。应由资料准备环节根据名称检索、存储可追溯公开资料供各篇共用，用户不必额外填写很多框。
7. 品牌优势还没有充分转化为工作细节。有原始服务依据，但正文主要通过重复名称和优势证明推荐；缺少围绕某个具体经营问题说明服务如何实施的厚度。项目材料同时提供全案、半托管、陪跑、基础曝光等模式，部分稿件却把曝光率GEO整体排除在试水客户之外，丢失了服务模式差异。
8. 原始资料的观点被放大为市场事实。例如材料强调第三方工具依赖，正文进一步写“没有自主技术，后两件就无从谈起”。这并不是必须新加审核器的问题，而是项目理解需要分清企业自述优势、可验证服务事实、编辑的合理解释，不把三者互相升级。
9. 标题像压缩稿单。选型标题把“避开错误”和“建立判断框架”两件事都装进去，后半句过长。标题应抓最有用的一个选择问题，余下交给摘要和正文，而不是增加硬性字数拦截。
10. 数量与叙述不完全一致。榜单摘要写五个维度，后文六条标准；选型开头四条，后文五维。需要编辑稿单内部统一这一篇的论述关系，而不是系统给所有类型设置统一维度数。

## 显示与配图

- 实际浏览器中，文章页已显示标题，正文保留同一H1又显示一次。
- 当前第一篇各服务商标题均为H2、20px，未观察到第一名比其他名小的旧问题；不同类型使用H2/H3本身不等于错乱。
- 正文前的图片带有旧TOP5名单，与本篇曝光率GEO、移山科技、企来客、欧博东方、光头牛哥名单不同。图文冲突不是CSS问题。
- 图片标为客户案例图，但呈现的是榜单宣传版式；分类和说明需要真实反映图片内容。
- 后续展示修改应独立处理标题渲染、图片语义匹配、阅读区域与滚动，不让写作模型承担页面排版修补。

## 下一轮生产侧改进顺序

1. 保留当前工作流和冻结Skill。先在选题交接中区分购买阶段、主要决策问题和相关品牌优势，使类型变化之外也有实质变化。
2. 编辑交接形成明确推荐答案，并统筹各部分新增信息。优势原文只需在相关位置展开，其他段落沿已建立的结论继续推进。
3. 从已有材料中提炼服务做法；同行资料按名称联网准备并跨篇共用。没有实测记录时不把能力分析说成已发生的测试。
4. 写作交接保留全文和前文，让每个工序继续完成文章，不打印编辑旁白。不增加生成后换词、扩写或评分打回。
5. 单独修复标题重复与图片旧名单问题。

下一次先用同项目、不同决策处境生成少量文章对照；确认推荐明确度、信息增量和图文一致性改善后，再验证批量与其余类型。没有给本批虚拟豆包引用评分，也不将本地阅读评价等同于实际被引用概率。
